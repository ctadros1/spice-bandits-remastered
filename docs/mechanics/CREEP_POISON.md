## R190 original research

R190 is research only. Two independent original executions reproduce the complete 1,666,046-byte reference (see the validation record for its binding), with 4,608 direct cases and 143 ordered caller sequences. Runtime integration remains pending; the exact R187 packaged app and current R189 source helper are unchanged.

The full original `CCreep.EmitPoisonParticles` (0x7bc88, 60 bytes) selects radiation for type1, poison for type2, and freeze for type3. It writes literal release count1 to the selected existing root. Type3 only writes when raw creep+0x235 bit0 is clear. Null pointers and unknown selectors do nothing; actor death state is not checked here. `StopPoisonParticles` (0x7bcc4, 32 bytes) only handles types1/2 and writes0; it does not stop the freeze root. Constructor backup release counts are not restored by these functions.

Full `CPoison.DoDamage` (0xe17c0, 396 bytes) and `DoSlowDown` (0xe16bc, 260 bytes) traverse the supplied global actor vector in order. States2/3 and raw resource kinds other than1 are ineligible. Distance is a float32 circular distance normalized by supplied map height, with a strict range boundary. Damage increments its own exposure counter before invoking the damage callback, then calls Emit with its chemical/radiation selector. For a damage cloud, an out-of-range/ineligible actor receives Stop for that selector and is removed from the cloud’s tracked range list. An in-range actor is appended only if no tracked ID matches. A recording callback that sets state3 still returns to the unconditional Emit call; actual original lethal damage and reward side effects are outside this fixture.

Slow clouds increment only the slowdown counter, call Emit(type3), and run the full original creep slowdown combination (0x7a904, 32 bytes). The resource amount is divided by powers of two and the original negative100 literal. Supplied positive50 therefore produces0.5 then0.75, combined as0.375. Negative/zero parameters are explicit supplied boundaries, not campaign changes. Full `EraseCreepInRange` (60 bytes), reserved vector push (40 bytes), and `EraseAllCreepsInRange` (48 bytes) execute; clear stops the selected alias in tracked vector order and empties it. ldexpf and overlapping memmove are explicit host stubs. Allocation is avoided by supplied reserved capacities.

Emitter ownership is independent for poison and radiation. Two same-type clouds demonstrate order sensitivity: an actor inside the first but outside the last finishes with that alias stopped; reversing the calls finishes with it emitting. A different-type cloud stops its own alias while preserving the other. Aggregate “any exposure/any radiation” logic cannot reproduce these ordered calls.

The actual source-native R189 Simulation diagnostic confirms a live bridge gap: chemical and radiation cloud exposure counters become positive, but their owned particle release rates remain0 in all four observed ticks. ProcessSpeed resets the counter before `refresh_creep` uses it. A Goo cloud followed by a chemical cloud also leaves poison_count2; original selected slow/damage callers leave separate counters1/1. These are preserved expected differences, not passing fidelity assertions. Raw report, exact diagnostic script/log and both independent original captures remain under builds/poison-*-r190-*.

The fixtures use supplied actor/resource/global-vector/root/position/count records and explicit ordered damage callbacks. They do not execute the resource loader, constructors, full CPoison.Update, actual damage/death/rewards, original particle integration, room/tower clock scheduling, sound or GPU. In particular, cloud expiry, parent activation, final particle tails and global cleanup timing require further recovery before full lifecycle identity can be claimed.
