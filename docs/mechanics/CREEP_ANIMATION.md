## Recovered behavior

`CCreep::ProcessSpeed0x7a924` computes separate float32 speed products, consumes a positive pending slowdown, and sets both animator divisors to1000/currentSpeed. Zero speed produces infinity. Both playback multipliers become0 when creep+0x20c holds a pointer to a player's freeze countdown; that field is not itself a timer.

`UseFreeze0x7bc1c` rejects creep states2/3 and otherwise attaches the supplied countdown pointer. `CCreepManager::FreezeCreeps0xfbddc` applies it only to creatures whose owner differs from the supplied player's ID. Newly spawned creatures do not inherit an earlier attachment. Optional auxiliary tracker fields are tested without assigning an unverified particle/footstep meaning to their owner.

`CRoom::ProcessPlayers0xd4080` reads whether the countdown is positive before decrementing it, subtracts delta in float32, truncates to an integer, clamps expiry to0, and plays freeze-off once. Thus the room freeze flag stays true during the expiry update. `UpdateGame0xd338c` calls waves before ProcessPlayers and creatures afterward: wave timing uses the preceding room flag; survival timing uses the updated flag. Full wave algorithms and complete room lifecycle do not execute in this new probe.

`CCreep::Update0x7e8d0` calls ProcessSpeed before `ProcessFreeze0x7bc3c`. ProcessFreeze copies the shared countdown and releases the pointer when it is nonpositive. On expiry, movement can resume with a released pointer while the animator multiplier remains0 from the earlier ProcessSpeed call. The following update resumes the animation.

The constructor0x78374 explicitly clears reset-on-name-change for both animators. Changing a walking direction preserves phase. The attack branch0x7cbfe..0x7cc1e explicitly stops and sets frame0 on both, including a currently invisible secondary. Full attack-entry/alignment/exit policy remains a separate caller comparison.

`CCreep::Render0x7f5c8` explicitly updates the primary before shadow/body. Its full animator Render then avoids a second update, setting the auto-update flag again on exit. The secondary updates only when submitted with nonzero corner alpha. `CCreepShadow::Render0xfc7b8` copies the primary animation/frame into an animated shadow; a static shadow uses the primary frame dimensions. Repeated original Render calls repeat the supplied delta. The Godot one-render-per-process bridge and held QA readbacks are an explicit scheduling adaptation.

## Retained failures and limits

That fixture/log is retained; explicitly clearing each reserved actor record makes the owner/state exclusions observable. The GDScript unit first used `Animation`, which shadows a native class, and later omitted the required third spawn_enemy argument. Both logs are retained. The latter deferred script error left a process alive; only that owned process was terminated, and a30-second unit watchdog was added. These repairs change harness setup, not expected original arithmetic or tolerances.

The probes do not run the original complete constructor/resource loader, clock producer, all attack/culling/death callers, mutable registry, pathfinding, global RNG, services or GPU.
