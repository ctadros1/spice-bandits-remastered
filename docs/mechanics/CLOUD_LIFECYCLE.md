R192 is original-code research only. Two separate original-code executions reproduce 73 supplied sequences, their full frame records, 61 particle-status cases and 900 emission-header cases. The validation record binds the exact count, bytes and SHA-256. Full selected CPoison.C2/Update/UpdateParticles, original selected damage/slow/Emit/Stop/list methods and reserved vector push bodies remain unchanged (2,820 bytes). Particle creation/update/destruction, random/vector, decals, sound, allocation/exception and damage are explicit callbacks. This is a caller chronology/header oracle, not original particle-physics, complete resource loading, GPU or whole-game execution.

The constructor starts active/not deleted with age0, emission age1000ms, no parents and empty particle/in-range vectors. A pending parent pauses cloud age, emission and damage while existing cloud particles still update. Raw parent+0x40 is checked first through word+4; raw parent+0x30 uses bit0 of byte+0x44 with the opposite readiness polarity. Once ready, the original clears that pointer, requests decals and requests its conditional sound. Actual parent producers are not executed here.

Cloud age and emission age use float32 additions. At age>=duration it marks deleted before creating another particle system or applying damage/slowdown. A live cloud emits when its timer reaches60ms for radiation or80ms otherwise, then resets the timer to0. Normal chemical/Goo systems receive25initial updates of f32(.05)seconds; radiation skips that warmup. Their new headers receive disable-after=f32(duration_ms*f32(.001)), in seconds. A non-radiation resource word8==1 doubles the system release interval. Static producer code carries Room.UpdateTowers’1..3loop through the manager’s third integer and C2’s resource+8 store; this is the three-tier bridge, while full XML/Objective-C loading remains outside the probe.

Particle removal tests the pre-update state. Positive active count, first-release=true or disable-after=0 keeps a system and calls Update. Otherwise the original destroys/deletes it and compacts the vector without skipping the shifted entry. A callback that changes active count to0 is observed for removal on the following call. Deleted clouds retain their object while any particle system remains. Only after the vector is empty does Update clear the object’s active flag and call StopPoisonParticles for every supplied global actor, in order. Non-radiation clouds use selector2 even for Goo; radiation uses selector1. The in-range list remains for the later destructor clear. Current R191 zones expire earlier and only clear their tracked list, so full lifecycle integration is still required.

The emission matrix covers supplied vectors, both map heights, zero/positive radii, both durations, tiers and raw rand/random values through signed31-bit maximum. It records exact caller-written positions, colors, intervals and disable-after words.
